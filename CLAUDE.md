# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

CSA Evaluation Calculator (displayed as **"Industrial Engineering Calculator"** in the UI, but the repo, package, manifest, CSV/PDF filenames, and service-worker cache prefix still use `csa-*`) — a single-page, installable PWA for evaluating manufacturing line efficiency: target output vs. actual output, quality pass rate, and a training/learning-curve plan. UI text is in Thai by default with English, Vietnamese, and Lao translations.

**Build model (as of the Vite migration).** The app is now built with **Vite** and written as **ES modules** — no more root-level `<script defer>` globals. Sources live in `src/`, static assets in `public/`, and `index.html` loads a single `<script type="module" src="/src/main.js">`. Each module `import`s what it needs and `export`s its public surface (the old `if (module.exports)` guards are gone; tests `import` from `../src/`). `npm run dev` serves with HMR, `npm run build` emits `dist/`, `npm run preview` serves the built output. The migration was staged as Phase 1 (Vite + ESM, behaviour-preserving); Firebase auth/Firestore (Phase 2), code obfuscation (Phase 3), and Vercel deploy (Phase 4) build on top — see `docs/plan.md` and `docs/plan-backend-firebase.md`.

The source files under `src/` (import graph, not load order — Vite/Rollup resolves it):

- `index.html` (~800 lines) — all markup: main form + feedback modal + formula modal + stopwatch modal + history/compare modal + Time Study config modal + onboarding overlay + in-app numpad + settings modal + tutorial/quiz/certificate overlay. No inline `on*` handlers — every interactive element carries `data-action` (+ optional `data-arg`), bound in `src/wiring.js`.
- `style.css` (~2100 lines) — all styling (numbered sections via comment headers, e.g. `/* ---- 9. Inputs & Layout ---- */`). Stays at repo root; Vite bundles it via the `index.html` `<link>`.
- `src/main.js` — **entry point**. Registers the service worker, stamps the footer version, installs the no-zoom guards, runs the init sequence (theme / GA / restore state / language / first `calculateAll`), and `import`s `wiring.js`. This is the file `index.html` loads.
- `src/wiring.js` — all event binding that used to be inline `on*` attributes: the 8 recalc inputs (`FORM_FIELD_IDS`) + `tsErrorInput` bound by id, and one delegated `click` handler on `[data-action]` (+`data-arg`) covering every button (header menu, SAM unit, stopwatch, Time Study, onboarding, chart toggle, tutorial). Adding a button = add its `data-action` in markup + one entry in the `ACTIONS` table here.
- `src/state.js` — **shared cross-module state + helpers**, extracted to break the app↔chart/history/tutorial circular dependency: `currentLang` (live binding, mutated via `setCurrentLang`), `t()` (i18n lookup with th fallback), `gaTrack()`, `pcsPerHr`, and the GA4 config. Imported by app/chart/history/tutorial.
- `src/version.js` — **single source of truth for `APP_VERSION`** (`export const`). `main.js` stamps the footer (`#appVersion`); `app.js` writes the CSV "App version" row; `public/sw.js` keeps a matching `csa-vX.Y.Z` literal (its own worker context can't import the module); `test/version.test.js` fails the build if footer / `public/sw.js` / `package.json` drift from it. Also sets `self.APP_VERSION` for the SW.
- `src/calc.js` — pure calc: `parseNum` (comma-tolerant number parse), `pcsFromEff`, `calcAvgMin`, `calcActualEff`, `newSamFromEff`, `calcActualPcsPerHr`, `calcPassRate`, `calcTrainingDay`. No DOM access. Every DOM number read in `app.js`/`history.js` goes through `parseNum` so a comma decimal (TH/VN/LA) doesn't silently zero the field.
- `src/timeutil.js` — pure time + Time Study helpers: `fmtSw` / `fmtSec2` / `fmtSec4` (formatters), `snapLapMs` (10 ms display-resolution snap), `T_TABLE` + `tsTValue` (two-tailed Student's t critical values, df 1–30), `computeSampleSize(laps, confidence, errorPercent)` (sample-SD with Bessel's `n-1`, returns `{n, mean, sd, df, tVal, N_raw, N}`), CSV helpers `csvEscape` / `csvRow` / `csvBuild` (RFC 4180 with UTF-8 BOM for Excel Thai support). No DOM access.
- `src/translations.js` — flat i18n dictionary keyed by `th`/`en`/`vn`/`la`; `export const translations`, consumed by `t()` (state.js) + `changeLanguage()` (app.js).
- `src/chart.js` — hand-built inline SVG learning-curve chart (no charting library). Owns `chartMode` ('pcs' | 'eff'), the `_chartCache` (mutated by `app.js` via `setChartCache` / `resetChartAnimation`), the one-shot line-draw animation flag, `setChartMode`, `renderChartFromCache`, `renderSVGChart`. Draws with `var(--...)` tokens so it re-themes automatically. Imports `currentLang` / `pcsPerHr` / `t` from `state.js`.
- `src/history.js` — saved evaluations + compare table. Owns `csa_history_v1` storage, `saveCurrentToHistory`, `deleteHistoryEntry`, `setHistoryNote`, the history-modal DOM refs **and their event wiring**, `renderHistoryList` / `renderCompareTable`. Imports calc helpers from `calc.js`, `t`/`currentLang`/`pcsPerHr`/`gaTrack` from `state.js`, and `getSamMinutes` from `app.js` (runtime-only call, so the app↔history import cycle is safe). **This is the seam** the Phase 2 Firestore backend swaps through.
- `src/tutorial.js` — in-app learning centre: guided lessons (real app screenshots in `public/assets/tutorial/`), a comprehension quiz, and a canvas-rendered modern e-certificate. Renders the whole flow (category home → lesson viewer → quiz → result → certificate) into `#tutorialBody`, same "generate the DOM in JS" pattern as `history.js` (its generated buttons emit `data-action`). Content lives as `{ th, en }` objects resolved by `L()` (Thai-first, falls back to Thai). Progress persists in `csa_tutorial_v1`. Imports `currentLang` / `gaTrack` from `state.js`. `test/tutorial.test.js` fails the build if a lesson points at a missing screenshot (checked in `public/assets/tutorial/`) or a quiz answer index is out of range.
- `src/app.js` (formerly `script.js`) — the rest: stopwatch state machine + rAF ticker, `calculateAll` recompute pipeline, Time Study UI wiring, ambient-status setters, feedback modal + offline queue, `FORMULA_DEFS` + `openFormulaModal`/`closeFormulaModal`, PWA install prompt, first-run onboarding, theme toggle, GA4 loader, numpad. Exports every function `main.js`/`wiring.js` call; the init block that ran at the bottom moved to `main.js`.
- `public/sw.js` — service worker: network-first with 3 s timeout, cache fallback for GET, cached-index.html fallback for navigations, synthetic 503 for anything else. Bump `CACHE = 'csa-vX.Y.Z'` on every deploy. **Note:** its `ASSETS` list still names the pre-Vite flat filenames and will be reworked in Phase 4 (`vite-plugin-pwa` injectManifest) to precache Vite's hashed output; until then its `install` addAll may no-op, which only affects offline precache, not online use.
- `public/manifest.json` / `public/icon.svg` — PWA manifest and icon (copied verbatim to `dist/` root by Vite).

`package.json`, `vite.config.js`, and `test/` drive the build + `node:test` unit tests.

## Editing philosophy (important)

**Fix at the system level, never spot-patch blindly.** Before changing any line, trace what it touches across the whole app and fix every dependent point — don't just silence the symptom in front of you. Concretely: a value that appears in more than one place gets **one source of truth** the others read from (see `version.js` → footer + CSV + the version-sync test), not N hand-synced copies; a shared behavior (parsing, formatting, rounding) becomes **one helper routed everywhere** (see `parseNum` used by every DOM number read), not a fix in the one field that was reported; and when a change ripples (e.g. the seconds field accepting decimals) update **all** the consumers — input `pattern`/`inputmode`, the calc, every display, the formula modal, CSV, the stopwatch bridge — plus the tests and this file. If a drift can recur, add a test that fails the build when it does. Leave the system more consistent than you found it, not just locally unbroken.

## Development

The repo now has a **Vite build**. Common commands:

```bash
npm install       # once, to pull Vite + plugins (and later firebase)
npm run dev       # dev server with HMR at http://localhost:5173
npm run build     # emit dist/ (what gets deployed)
npm run preview   # serve the built dist/ to sanity-check a production build
npm test          # node:test unit tests (pure modules) — no dev server needed
```

Serve over http(s) (dev/preview), not `file://` — ES modules and (in Phase 2) Firebase auth require an http origin.

**Bumping the version:** edit `APP_VERSION` in `src/version.js` (the canonical value — footer + CSV read it at runtime) **and** the matching `const CACHE = 'csa-vX.Y.Z'` literal in `public/sw.js`. The `sw.js` byte change is what forces old clients to drop stale caches (the fetch handler is network-first, but the cache name is the bust signal), so it can't be derived from the module — it's duplicated on purpose and locked to `APP_VERSION` by `test/version.test.js`. Also bump `package.json`'s `version` to match (the same test enforces it). `npm test` fails if any of the four drift.

Run `npm test` (Node's built-in `node:test` runner, no dependencies) to check the pure modules — `calc.js` (incl. `parseNum`), `timeutil.js` (formatters + T-table + sample-size + CSV), `translations.js` (dictionary integrity + fallback chain + placeholder-token preservation), `version.js` (version-sync guard across `public/sw.js`/`package.json`/footer), and `tutorial.js` (lesson/quiz integrity + screenshot existence). Tests `import` from `../src/`. Current coverage: 105 tests across `test/calc.test.js`, `test/timeutil.test.js`, `test/translations.test.js`, `test/version.test.js`, `test/tutorial.test.js`.

**Tutorial screenshots** (`public/assets/tutorial/*.png`) are real captures of the running app, not mockups. To regenerate them after a UI change, serve the app (`npm run dev`) and drive it with a headless browser (Playwright), filling fields / opening modals into each state and screenshotting — the app renders Thai via the system TLWG font. Keep the filenames stable; `tutorial.js` and `public/sw.js` reference them by name and `test/tutorial.test.js` asserts each exists.

Screenshots are **language-specific**: the Thai captures live flat in `public/assets/tutorial/` (the default/fallback base), and each other language overrides with the **same filename** in its own subfolder — `public/assets/tutorial/en/`, `.../vn/`, `.../la/`. `_stepImgSrc(file)` in `tutorial.js` resolves the path for `currentLang` (Thai → flat, others → `<lang>/<file>`), and the lesson `<img>` has an `onerror` fallback to the Thai capture so a not-yet-added language image never shows broken. The naming convention and the filename→lesson map live in `public/assets/tutorial/README.md` (plus a per-folder checklist in each `<lang>/README.md`); `test/tutorial.test.js` checks the base Thai set exists and that the language folders are present. Only the Thai set's existence is enforced — other languages are filled in over time.

**Do not open a browser preview to visually verify UI/CSS changes in this project.** The user does that verification themselves and is better positioned to judge it. After editing code, confirm correctness through reading the code, `npm test`, `npm run build`, and static checks — don't launch `preview_start` or drive the Browser pane for this repo unless the user explicitly asks for it.

**Never `git push` (or merge to `main`, or otherwise publish) unless the user explicitly tells you to in that turn.** This repo currently deploys to GitHub Pages (`pepsi1219.github.io`) and is migrating to Vercel (Phase 4), so a push goes live immediately. Committing locally is fine when asked, but pushing/merging always requires an explicit, current instruction — a push from an earlier request does not authorize the next one.

## Architecture

**Single global calculation pipeline.** Every recalc input is bound to `calculateAll()` in `wiring.js` (by id, from `FORM_FIELD_IDS`). `calculateAll()` in `app.js` reads all form fields fresh each call, computes four sections in order, and writes results back into readonly fields — there is no separate state object for form data; the DOM *is* the state:
1. **Target**: `targetDisplay` from SAM value + efficiency target
2. **Actual**: cycle time and actual efficiency/output from recorded time + count
3. **Quality**: pass rate from pass/fail quantities
4. **Training plan**: generates day-by-day cards (`#trainingGrid`) and feeds `_chartCache`, which `renderChartFromCache()` / `renderSVGChart()` render as a hand-built inline SVG line chart (no charting library) showing the learning-curve gap between current and target efficiency.

**Stopwatch modal (`sw` object)** is a separate self-contained timer with its own state machine (`lap` vs `single` mode, running/paused/finalized, `sw.laps`), independent of `calculateAll()`. Uses `performance.now()` monotonic time + `requestAnimationFrame` at ~30 fps for battery + NTP-jump safety. On each `Lap` (or the final `Stop` in lap mode), the elapsed slice is snapped to 10 ms via `snapLapMs()` **on capture** so stored lap value == displayed value — hand-calculating SD from what's on screen returns the same number as the app. Closing the modal mid-run **preserves the in-progress lap** (sets `sw.paused=true`) so users don't silently lose data. The Time Study "required N" row + Continue button below the summary calls `computeSampleSize` from `timeutil.js`. `swSaveToForm()` is the only bridge to the main form.

**In-app numpad.** Every editable numeric field carries `inputmode="none"` (so the mobile OS keyboard never opens — physical keyboards still type, since `inputmode` only suppresses the on-screen one) plus `data-numpad="int|decimal"` and `data-numpad-label="<translation key>"`. A delegated click handler in `app.js` (`openNumpad`) opens the bottom-sheet `#numpadModal`; each key rewrites the field's `.value` and **re-fires a native `input` event**, so the field's `input` listener in `wiring.js` (`calculateAll` / `tsRecalculate`) runs unchanged — the numpad is a pure input surface and duplicates no recompute logic. The `.` key is hidden for `int` fields; the numpad normalizes a comma to a dot and strips a trailing dot on close. To add a numeric field, give it those three attributes (and a `data-numpad-label` key present in all four languages) — nothing else to wire. The two fields inside the stopwatch / Time-Study modals (`swRoundsInput`, `tsErrorInput`) are `type="text"` for this reason (uniform decimal handling; the numpad sheet at `z-index:9000` stacks above those modals).

**iOS keyboard handling.** `visualViewport` resize listener translates the sticky save panel above the on-screen keyboard so the Save button never hides beneath it.

**No zoom (native-app feel).** The page can't be pinch- or double-tap-zoomed, so it behaves like an installed app. Three layers, because no single one covers every browser: the viewport meta (`maximum-scale=1.0, user-scalable=no`), `html { touch-action: pan-x pan-y }` in `style.css` (allows scroll, blocks pinch/double-tap — Android), and a `gesturestart`/`gesturechange`/`gestureend` `preventDefault` in `main.js` (iOS Safari ignores the first two). Single-finger scrolling and desktop browser zoom (Ctrl +/-) are deliberately untouched — this only removes touch page-scaling.

**Settings + Learning centre.** The header overflow menu opens a **Settings modal** (`#settingsModal`, `openSettingsModal`) that consolidates the theme toggle, the 4-language picker (both moved out of the overflow menu — they keep their original ids/classes so `toggleTheme()` and the `changeLanguage()` wiring are untouched), and the **tutorial launcher**. The tutorial itself (`tutorial.js`) is a full-screen overlay stepping category home → lesson viewer → quiz → result → certificate; the quiz card unlocks only once every lesson is marked done, and passing it (≥ `QUIZ_PASS_PCT`) unlocks the certificate. Language changes re-render an open tutorial via `tutorialOnLangChange()` (called from `changeLanguage()`), since its content is JS-rendered through `L()` rather than `data-key` swaps. The certificate is drawn on an off-screen `<canvas>` (`#certCanvas`) and downloaded as PNG — no library, no server; the learner's name + a generated `IEC-…` id persist in `csa_tutorial_v1`.

**Ambient status.** `#actualEffPerc`, `#actualPcs`, and `#passRate` get `data-status="ok|warn|bad"` set by `setStatus()` from `calculateAll()`, driven by thresholds in `statusForEfficiency()` / `statusForPassRate()`. CSS in `style.css` translates the attribute into background + text color (using the `--status-*` tokens) so line supervisors can scan a shift at a glance.

**Formula modal.** Every computed field's `<label>` is a `.fx-label` with `data-fx="<key>"` and a small ⓘ icon. A document-level click-delegation handler in `app.js` opens `#formulaModal`, which reads the matching entry in `FORMULA_DEFS` (keyed by `target_pcs` / `new_sam` / `avg_sec` / `avg_min` / `actual_eff` / `actual_pcs` / `pass_rate`) and shows three blocks: **สูตร** (translated formula string), **คำอธิบาย** (translated description), and **ค่าที่คุณป้อน** (each def's `compute()` reads current form inputs and returns a substituted expression + result; returns `null` when inputs are missing → the modal shows `fx_no_data` instead). When adding a new computed field, add its `<label class="fx-label" data-fx="...">` in `index.html`, an entry in `FORMULA_DEFS`, and the `fx_formula_<key>` + `fx_desc_<key>` translation pair to all four language blocks (the translations test enforces parity).

**i18n** is a flat `translations` object (in `translations.js`) keyed by language code (`th`/`en`/`vn`/`la`) with string keys matching `data-key` attributes on elements (class `lang-text`). `changeLanguage()` walks the DOM and swaps text content (and `[data-key-placeholder]` attributes for input placeholders); `t(key)` is the lookup helper used inside JS-generated HTML (training cards, chart labels, compare table, N-row breakdown). When adding new UI copy, add the key to all four language blocks and reference it via `data-key="..."` (static markup) or `t('key')` (dynamically generated markup) — otherwise text falls back to Thai or the raw key. `test/translations.test.js` enforces this: it fails the build if `en`/`vn`/`la` are missing any key present in `th`, if any value is empty, or if a translation lost a `{placeholder}` token. Chosen language persists to `localStorage` under `csa_lang`.

**Persistence (`localStorage`):**
- Form auto-save (`csa_form_v1`) in `app.js` — every `calculateAll()` call ends with `saveFormState()`; `restoreFormState()` runs once at init.
- History (`csa_history_v1`) in `history.js` — explicit "Save current" via `saveCurrentToHistory()` snapshots inputs + computed results + optional shift-handover note (`entry.note`, max 200 chars, editable per row). Capped at `HISTORY_MAX` (100), FIFO-trimmed. Compare view lets the user pick 2+ entries → side-by-side table.
- Theme (`csa_theme`), language (`csa_lang`), session count (`csa_session_count`, used by the PWA install-prompt gate), onboarding-seen (`csa_onboarded_v1`), and feedback offline queue (`csa_feedback_queue_v1`, cap 20 entries) — each follows the same read-on-init / write-on-change pattern.

**Design tokens** (`style.css` §1): all colors are CSS custom properties on `:root`. A parallel dark token set applies under `@media (prefers-color-scheme: dark)` by default, or via `:root[data-theme="dark"]`/`[data-theme="light"]` when the user explicitly toggles (`toggleTheme()`, persisted to `csa_theme`). The hand-built SVG chart in `renderSVGChart()` draws with `var(--...)` tokens, so it re-themes automatically. Three semantic families to keep straight when adding UI:
- `--accent-*` (indigo) — brand, target / plan surfaces, primary actions. `--accent-grad` is **reserved for the primary CTA + brand mark only** (using it everywhere is what makes the app read as AI-scaffolded).
- `--accent-teal-*` — "actual / measured" surfaces (differentiates shop-floor readouts from the plan). Applied via `.actual-section` scope.
- `--status-{ok,warn,bad}-*` — threshold-driven ambient tint on result values. Semantic, never used as brand.

**External integrations, both feature-flagged in `app.js` / `state.js`:**
- Feedback modal submits to a Google Form via `fetch(... mode: 'no-cors')` — controlled by `GFORM_ENABLED` / `GFORM.url` / `GFORM.entry.*`. `no-cors` means the fetch always resolves opaquely (server errors are invisible); the mitigation is: if `!navigator.onLine`, submissions get queued in `csa_feedback_queue_v1` and drained on `online` event (and once at startup). The real fix for reliable ACKs is a Cloudflare Worker / Supabase Edge proxy — not yet built.
- Google Analytics 4 is lazy-injected via `initGA4()` — controlled by `GA4_ENABLED` / `GA4_MEASUREMENT_ID`. Events are fired through `gaTrack(eventName, params)`; feature-usage events (`use_quality_section`, `use_training_plan`) are tracked once per session via the `_tracked` flags to avoid re-firing on every keystroke.

**PWA install + onboarding:**
- `beforeinstallprompt` is stashed on `window`; the header install chip (`#installBtn`) reveals only after the 2nd session (`csa_session_count`) and only when not already in standalone mode. Silent on iOS Safari (event never fires).
- First-run 3-screen onboarding tour (`#onboardingOverlay`) shows once, persisted via `csa_onboarded_v1`. Skip button always available. `showOnboardingIfNeeded()` runs from init.

**PWA/offline**: `sw.js` pre-caches the core asset list on install (bump `ASSETS` when adding new JS/CSS/JSON) and uses a **network-first with 3 s timeout** fetch strategy. Fallback cascade: cached response → cached `index.html` (for navigation requests) → synthetic 503. Never resolves to `undefined` (which would throw inside `respondWith` and show the browser's native offline page). `index.html` also sets no-cache HTTP meta tags so the HTML shell itself is never cached client-side — only the service worker's own cache controls offline behavior.

**Export:**
- **CSV** (`exportCSV()` in `app.js`) — bilingual key/value rows via `csvBuild` / `csvRow` / `csvEscape` in `timeutil.js`. UTF-8 BOM prepended so Excel opens Thai correctly.
- **PDF** — browser's native "Save as PDF" via `printReport()` → `window.print()`. Print stylesheet (`@page A4 portrait`, forced color, single-column, safe-area-friendly, self-referential URLs) is authored to make the PDF audit-ready without shipping jsPDF or fighting Thai font embedding.
