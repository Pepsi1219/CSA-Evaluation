# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

CSA Evaluation Calculator (displayed as **"Industrial Engineering Calculator"** in the UI, but the repo, package, manifest, CSV/PDF filenames, and service-worker cache prefix still use `csa-*`) — a single-page, installable PWA for evaluating manufacturing line efficiency: target output vs. actual output, quality pass rate, and a training/learning-curve plan. UI text is in Thai by default with English, Vietnamese, and Lao translations.

**Build + deploy (current).** The app is built with **Vite** and written as **ES modules** — no more root-level `<script defer>` globals. Sources live in `src/`, static assets in `public/`, and `index.html` loads a single `<script type="module" src="/src/main.js">`. Each module `import`s what it needs and `export`s its public surface (the old `if (module.exports)` guards are gone; tests `import` from `../src/`). `npm run dev` serves with HMR, `npm run build` emits `dist/`, `npm run preview` serves the built output.

**Ships to production on Vercel at https://csa-evaluation.vercel.app** (auto-deploys on push to `main`). Firebase Auth gates the app (employee-code login → synthesised `<code>@ie-calc.internal` / same-value password against Firebase Auth's allowlist) and Firestore stores per-user history + tutorial progress. All four migration phases are merged and live — see [docs/plan.md](docs/plan.md) for the timeline and [docs/plan-backend-firebase.md](docs/plan-backend-firebase.md) for the strategy doc.

The source files under `src/` (import graph, not load order — Vite/Rollup resolves it):

- `index.html` (~1200 lines) — all markup: main form + feedback modal + formula modal + stopwatch modal (Lap / Single / IE panels: intro-gate → chooser → setup → capture → result) + history/compare modal + Time Study config modal + onboarding overlay + in-app numpad + settings modal + tutorial/quiz/certificate overlay. No inline `on*` handlers — every interactive element carries `data-action` (+ optional `data-arg`), bound in `src/wiring.js`.
- `style.css` (~3400 lines) — all styling (numbered sections via comment headers, e.g. `/* ---- 9. Inputs & Layout ---- */`). Stays at repo root; Vite bundles it via the `index.html` `<link>`.
- `src/main.js` — **entry point + boot orchestrator**. Registers the service worker, stamps the footer version, installs the no-zoom guards, runs three-phase boot (Phase A: theme/lang; Phase B: `initFirebase()` + `onAuthChange` gate → `showLoginOverlay` or `enterApp`; Phase C: `enterApp` awaits `subscribeHistory` + `subscribeTutorial` in parallel + `migrateLocalHistory` + `reconcileTutorial`, then runs the app init sequence). Owns the login-card wiring (form submit, eye toggle, language flag row). Dismisses `body.booting` via `endBoot()` from both paths so the splash never lingers. `import`s `wiring.js`.
- `src/wiring.js` — all event binding that used to be inline `on*` attributes: the 8 recalc inputs (`FORM_FIELD_IDS`) + `tsErrorInput` bound by id, and one delegated `click` handler on `[data-action]` (+`data-arg`) covering every button (header menu, SAM unit, stopwatch, Time Study, onboarding, chart toggle, tutorial). Adding a button = add its `data-action` in markup + one entry in the `ACTIONS` table here.
- `src/state.js` — **shared cross-module state + helpers**, extracted to break the app↔chart/history/tutorial circular dependency: `currentLang` (live binding, mutated via `setCurrentLang`), `t()` (i18n lookup with th fallback), `gaTrack()`, `pcsPerHr`, and the GA4 config. Imported by app/chart/history/tutorial.
- `src/version.js` — **single source of truth for `APP_VERSION`** (`export const`). `main.js` stamps the footer (`#appVersion`); `app.js` writes the CSV "App version" row; `src/sw.js` keeps a matching `csa-vX.Y.Z` literal (its own worker context can't import the module); `test/version.test.js` fails the build if footer / `src/sw.js` / `package.json` drift from it. Also sets `self.APP_VERSION` for the SW.
- `src/calc.js` — pure calc: `parseNum` (comma-tolerant number parse), `pcsFromEff`, `calcAvgMin`, `calcActualEff`, `newSamFromEff`, `calcActualPcsPerHr`, `calcPassRate`, `calcTrainingDay`. No DOM access. Every DOM number read in `app.js`/`history.js` goes through `parseNum` so a comma decimal (TH/VN/LA) doesn't silently zero the field.
- `src/timeutil.js` — pure time + Time Study helpers: `fmtSw` / `fmtSec2` / `fmtSec4` (formatters), `snapLapMs` (10 ms display-resolution snap), `T_TABLE` + `tsTValue` (two-tailed Student's t critical values, df 1–30), `computeSampleSize(laps, confidence, errorPercent)` (sample-SD with Bessel's `n-1`, returns `{n, mean, sd, df, tVal, N_raw, N}`), CSV helpers `csvEscape` / `csvRow` / `csvBuild` (RFC 4180 with UTF-8 BOM for Excel Thai support). No DOM access.
- `src/translations.js` — flat i18n dictionary keyed by `th`/`en`/`vn`/`la`; `export const translations`, consumed by `t()` (state.js) + `changeLanguage()` (app.js).
- `src/chart.js` — hand-built inline SVG learning-curve chart (no charting library). Owns `chartMode` ('pcs' | 'eff'), the `_chartCache` (mutated by `app.js` via `setChartCache` / `resetChartAnimation`), the one-shot line-draw animation flag, `setChartMode`, `renderChartFromCache`, `renderSVGChart`. Draws with `var(--...)` tokens so it re-themes automatically. Imports `currentLang` / `pcsPerHr` / `t` from `state.js`.
- `src/history.js` — saved evaluations + compare table. Owns `csa_history_v1` (local fallback) + the Firestore seam, `saveCurrentToHistory`, `deleteHistoryEntry`, `setHistoryNote`, the history-modal DOM refs **and their event wiring**, `renderHistoryList` / `renderCompareTable`. `loadHistory()` returns the Firestore-fed cache when signed in, else localStorage; writes route to `fs*` in `auth.js` when signed in and also mirror locally. Live re-render of the open modal on snapshot change via `subscribeHistoryChange`. Imports calc helpers from `calc.js`, `t`/`currentLang`/`pcsPerHr`/`gaTrack`/`HISTORY_MAX` from `state.js`, and `getSamMinutes` from `app.js` (runtime-only call, so the app↔history import cycle is safe).
- `src/auth.js` — Firebase Auth + Firestore data layer. `initFirebase()` (idempotent) sets up Firestore's `persistentLocalCache` for offline resilience; `signInWithCode(code)` synthesises `<code>@ie-calc.internal` + password `<code>` and calls Firebase Auth; `emailToCode` strips the suffix for display. Owns two subscriptions/caches: **history** (`subscribeHistory` → `getHistoryCache` + `fsSaveEntry`/`fsDeleteEntry`/`fsSetNote`) and **tutorial** (`subscribeTutorial` → `getTutorialCache` + `fsSaveTutorial`). Two one-shot idempotent reconcilers per uid: `migrateLocalHistory` (writeBatch of local `csa_history_v1` entries, flag `csa_migrated_<uid>`) and `reconcileTutorial` (union-merge local into cloud, flag `csa_tut_reconciled_<uid>`). Pure exports for unit tests: `mergeHistorySnapshot` (dedupe/sort ts desc/cap `HISTORY_MAX`) and `mergeTutorialProgress` (union `done`, better quiz, earliest cert). `FIREBASE_ENABLED` is derived from `import.meta.env.VITE_FIREBASE_API_KEY`; when unset the whole layer is a no-op and the app boots into localStorage-only mode.
- `src/tutorial.js` — in-app learning centre: guided lessons (real app screenshots in `public/assets/tutorial/`), a comprehension quiz, and a canvas-rendered modern e-certificate. Renders the whole flow (category home → lesson viewer → quiz → result → certificate) into `#tutorialBody`, same "generate the DOM in JS" pattern as `history.js` (its generated buttons emit `data-action`). Content lives as `{ th, en }` objects resolved by `L()` (Thai-first, falls back to Thai). Progress persists via the same seam as history — `loadTutProgress()` returns the Firestore cache when signed in, else `csa_tutorial_v1`; `saveTutProgress(p)` writes locally + (when signed in) union-merges with cloud through `fsSaveTutorial`. `openTutorial()` preloads every distinct step image via `new Image().src` so lessons don't wait on the network. Imports `currentLang`/`gaTrack` from `state.js`, tutorial data-layer from `auth.js`. `test/tutorial.test.js` fails the build if a lesson points at a missing screenshot (checked in `public/assets/tutorial/`) or a quiz answer index is out of range.
- `src/app.js` (formerly `script.js`) — the rest: stopwatch state machine + rAF ticker, `calculateAll` recompute pipeline, Time Study UI wiring, ambient-status setters, feedback modal + offline queue, `FORMULA_DEFS` + `openFormulaModal`/`closeFormulaModal`, PWA install prompt, first-run onboarding, theme toggle, GA4 loader, numpad. Exports every function `main.js`/`wiring.js` call; the init block that ran at the bottom moved to `main.js`.
- `src/sw.js` — service worker source. **Vite-plugin-pwa (injectManifest)** rewrites `self.__WB_MANIFEST` at build time with the list of hashed filenames Vite emitted, and copies the result to `dist/sw.js`. Fetch is network-first with a 3 s timeout, cache fallback for GET, cached-`/index.html` fallback for navigations, synthetic 503 otherwise. Bump `CACHE = 'csa-vX.Y.Z'` on every deploy — that literal is the cache-bust signal and stays out of `version.js` on purpose (SW context can't import the module). Uses per-URL `cache.add(...).catch()` instead of `addAll` so one missing file doesn't kill the whole install.
- `public/manifest.json` / `public/icon.svg` — PWA manifest and icon (copied verbatim to `dist/` root by Vite).

`package.json`, `vite.config.js`, and `test/` drive the build + `node:test` unit tests.

## Product priorities (LOCKED)

**Speed first, safety second — in that order.** This app runs on the shop floor on cheap phones over factory Wi-Fi. Any change is measured against **cold-start time, first tap latency, and how quickly the tutorial images resolve** before anything else. Concretely:

1. **Speed is priority #1.** If a defensive layer (obfuscator pass, extra network round-trip, extra `await`, blocking listener, synchronous localStorage read on the hot path, extra `<img loading="lazy">`) makes the app perceptibly slower, it is **out**. The user has already rejected `controlFlowFlattening`, `deadCodeInjection`, `debugProtection`, `selfDefending`, and base64 `stringArrayEncoding` for this reason — do not reintroduce them (see `vite.config.js` comments).
2. **Safety is priority #2.** Firestore Rules + Firebase Auth allowlist + the current light obfuscator config (identifier rename + string hide + minify) are the guard. Anything beyond that must earn its cost in benchmarks, not intuition.
3. Never trade speed for a marginal deterrence gain. "It makes reverse-engineering slightly harder" is not enough — a real security control (Rules on a resource the user could otherwise reach) is. If in doubt, keep the faster path and tell the user why.
4. Ship perf regressions the moment they're detected. Don't wait to bundle them with a "cleanup PR" later — a slower app is a broken app to the operator.

## Editing philosophy (important)

**Fix at the system level, never spot-patch blindly.** Before changing any line, trace what it touches across the whole app and fix every dependent point — don't just silence the symptom in front of you. Concretely: a value that appears in more than one place gets **one source of truth** the others read from (see `version.js` → footer + CSV + the version-sync test), not N hand-synced copies; a shared behavior (parsing, formatting, rounding) becomes **one helper routed everywhere** (see `parseNum` used by every DOM number read), not a fix in the one field that was reported; and when a change ripples (e.g. the seconds field accepting decimals) update **all** the consumers — input `pattern`/`inputmode`, the calc, every display, the formula modal, CSV, the stopwatch bridge — plus the tests and this file. If a drift can recur, add a test that fails the build when it does. Leave the system more consistent than you found it, not just locally unbroken.

## Architecture

**Single global calculation pipeline.** Every recalc input is bound to `calculateAll()` in `wiring.js` (by id, from `FORM_FIELD_IDS`). `calculateAll()` in `app.js` reads all form fields fresh each call, computes four sections in order, and writes results back into readonly fields — there is no separate state object for form data; the DOM *is* the state:
1. **Target**: `targetDisplay` from SAM value + efficiency target
2. **Actual**: cycle time and actual efficiency/output from recorded time + count
3. **Quality**: pass rate from pass/fail quantities
4. **Training plan**: generates day-by-day cards (`#trainingGrid`) and feeds `_chartCache`, which `renderChartFromCache()` / `renderSVGChart()` render as a hand-built inline SVG line chart (no charting library) showing the learning-curve gap between current and target efficiency.

**Stopwatch modal (`sw` object)** is a separate self-contained timer with its own state machine (`lap` vs `single` mode, running/paused/finalized, `sw.laps`), independent of `calculateAll()`. Uses `performance.now()` monotonic time + `requestAnimationFrame` at ~30 fps for battery + NTP-jump safety. On each `Lap` (or the final `Stop` in lap mode), the elapsed slice is snapped to 10 ms via `snapLapMs()` **on capture** so stored lap value == displayed value — hand-calculating SD from what's on screen returns the same number as the app. Closing the modal mid-run **preserves the in-progress lap** (sets `sw.paused=true`) so users don't silently lose data. The Time Study "required N" row + Continue button below the summary calls `computeSampleSize` from `timeutil.js`. `swSaveToForm()` is the only bridge to the main form.

**IE Time Study mode.** The stopwatch modal has a third tab beyond Lap/Single: **IE** — a heavier, element-by-element flow aimed at Industrial-Engineering staff (CSA/QCO users stay on Lap/Single for casual Cycle Time). Tab structure and gating live in `src/app.js` (`sw.mode`, `swSetMode`, `_swApplyMode`, `_swSyncModePanels`), IE-specific state lives in the `ie` object next to it. Switching *into* IE from another mode surfaces `#ieIntroModal` first (`_ieShowIntroModal` + `ieIntroConfirm`/`ieIntroCancel`) so a non-IE user doesn't fall into the heavier flow by accident; re-tapping the IE tab while already in IE is a no-op and skips the gate. The mode-switching guard in `swSetMode` only blocks a switch when the CURRENT mode's timer is actively running (`sw.running` for Lap/Single, `ie.running` for IE) — earlier versions blocked any move to Lap/Single whenever `sw.elapsed > 0`, which trapped the user inside IE the moment `sw.elapsed` was non-zero from a persisted session. Once accepted, IE runs through four panels in order — `#ieChooserPanel` (pick flow: SAM vs Cycle Time) → `#ieSetupPanel` (rounds + Breakpoint count + per-element rating + shared allowances) → `#ieCapturePanel` (continuous timing; each tap on the big "จุด Breakpoint" button marks the next Breakpoint and the time lands in the live table immediately) → `#ieResultPanel` (per-element table with per-round observed times + x̄ + SD, plus RF/NT/ST for SAM; sample-size N moved out to the summary below). The **UI term "Breakpoint"** is what the internal API calls an element (`ie.elements[]`, `IE_PRESET_KEYS`, `_ieElemLabel`); the rename is copy-only. `ieSaveToForm()` writes the SAM result into `samInput` (switching unit to 'min') — the only bridge to the main form. Persistence: full `ie` state (setup, allowance, elapsed, readings, finalized) is mirrored to `csa_ie_v1` on every change so a mid-capture reload restores exactly where the user left off.

**IE capture-panel controls (three-button spec).** The capture panel uses the same `.sw-controls` circular-button row the Lap/Single page uses — primary green action on the RIGHT (thumb-reachable one-handed). Three discrete functions replace the old conflated `ieStartStop`:
- `ieStartTimer()` — from idle or paused → running (elapsed carried over so the same button doubles as resume).
- `iePauseTimer()` — running → paused, freezes `ie.elapsed` without finalizing. Readings stay put; the study is NOT ended.
- `ieResetTimer()` — wipes readings + elapsed + finalized flag with a `showConfirm` when there's data to lose. Auto-finalize still happens inside `ieTap` when the last breakpoint of the last round lands (that's the ONLY path to the result panel — no manual "finish" button). The "แก้ไขการตั้งค่า" step-back affordance is a small `.ie-back-chip` pill below the live table, matching the same chip in the setup panel and result panel (single visual language across all IE panels). The old Undo button is gone.

**IE setup — ± steppers and null preset.** Rounds, Breakpoint count, and the three Allowance percentages each use an `.ie-stepper` shell: the input keeps its full width; a stacked ± column pins absolutely to the right edge inside it, so tapping the value still opens the numpad while the buttons offer a quick nudge. `ieNudge(spec)` in `app.js` handles both integer (Rounds → clamp to `IE_ROUNDS_MAX`, Breakpoint count → `IE_ELEM_MAX`) and float allowances (clamp 0..95 via `_ieClampFloat`, step 1%, `Math.round(x*10)/10` guards float noise); after clamping it dispatches a native `input` event so `_ieOnSetupInput` runs untouched (persists + for elem count re-renders the list). A fresh `+ เพิ่ม` element now starts with `preset: null` (was `IE_PRESET_CUSTOM`) so the operator must pick a preset from a leading disabled `— เลือกขั้นตอน —` placeholder option; `ieStart` validation blocks capture if any row has `preset === null`. The restore path in `loadIEState` distinguishes `preset === null` (keep — freshly-added row saved mid-setup) from `preset === undefined` (legacy record — falls back to name-match / Custom as before), so old saved sessions still hydrate cleanly.

**IE result summary — mirrors the Lap-mode summary.** The totals section renders inside a real `.sw-stats-panel` with the same six-row shape the Lap page uses, computed over each fully-captured cycle's total observed time (one cycle = one "lap"): `sw_avg` / `sw_fastest` / `sw_slowest` / `sw_total` / `sw_std`, then TWO required-N rows — `t-test` (uses shared `_ts.confidence` / `_ts.error`) and `Maytag` (fixed 95%/±5% shortcut via `maytagN` from `ie.js`). The Lap-mode stopwatch summary also carries both required-N rows now, both computed from the shared `computeSampleSize` + `maytagN` helpers — fix a bug in one, it flows through the other. The `(t-test)` / `(Maytag)` label suffix sits OUTSIDE the `.lang-text` span so `changeLanguage()` doesn't wipe it on TH/EN/VN/LA switch.

**In-app numpad.** Every editable numeric field carries `inputmode="none"` (so the mobile OS keyboard never opens — physical keyboards still type, since `inputmode` only suppresses the on-screen one) plus `data-numpad="int|decimal"` and `data-numpad-label="<translation key>"`. A delegated click handler in `app.js` (`openNumpad`) opens the bottom-sheet `#numpadModal`; each key rewrites the field's `.value` and **re-fires a native `input` event**, so the field's `input` listener in `wiring.js` (`calculateAll` / `tsRecalculate`) runs unchanged — the numpad is a pure input surface and duplicates no recompute logic. The `.` key is hidden for `int` fields; the numpad normalizes a comma to a dot and strips a trailing dot on close. To add a numeric field, give it those three attributes (and a `data-numpad-label` key present in all four languages) — nothing else to wire. The two fields inside the stopwatch / Time-Study modals (`swRoundsInput`, `tsErrorInput`) are `type="text"` for this reason (uniform decimal handling; the numpad sheet at `z-index:9000` stacks above those modals).

**iOS keyboard handling.** `visualViewport` resize listener translates the sticky save panel above the on-screen keyboard so the Save button never hides beneath it.

**No zoom (native-app feel).** The page can't be pinch- or double-tap-zoomed, so it behaves like an installed app. Three layers, because no single one covers every browser: the viewport meta (`maximum-scale=1.0, user-scalable=no`), `html { touch-action: pan-x pan-y }` in `style.css` (allows scroll, blocks pinch/double-tap — Android), and a `gesturestart`/`gesturechange`/`gestureend` `preventDefault` in `main.js` (iOS Safari ignores the first two). Single-finger scrolling and desktop browser zoom (Ctrl +/-) are deliberately untouched — this only removes touch page-scaling.

**Settings + Learning centre.** The header overflow menu opens a **Settings modal** (`#settingsModal`, `openSettingsModal`) that consolidates the theme toggle, the 4-language picker (both moved out of the overflow menu — they keep their original ids/classes so `toggleTheme()` and the `changeLanguage()` wiring are untouched), and the **tutorial launcher**. The tutorial itself (`tutorial.js`) is a full-screen overlay stepping category home → lesson viewer → quiz → result → certificate; the quiz card unlocks only once every lesson is marked done, and passing it (≥ `QUIZ_PASS_PCT`) unlocks the certificate. Language changes re-render an open tutorial via `tutorialOnLangChange()` (called from `changeLanguage()`), since its content is JS-rendered through `L()` rather than `data-key` swaps. The certificate is drawn on an off-screen `<canvas>` (`#certCanvas`) and downloaded as PNG — no library, no server; the learner's name + a generated `IEC-…` id persist in `csa_tutorial_v1`.

**Ambient status.** `#actualEffPerc`, `#actualPcs`, and `#passRate` get `data-status="ok|warn|bad"` set by `setStatus()` from `calculateAll()`, driven by thresholds in `statusForEfficiency()` / `statusForPassRate()`. CSS in `style.css` translates the attribute into background + text color (using the `--status-*` tokens) so line supervisors can scan a shift at a glance.

**Formula modal.** Every computed field's `<label>` is a `.fx-label` with `data-fx="<key>"` and a small ⓘ icon. A document-level click-delegation handler in `app.js` opens `#formulaModal`, which reads the matching entry in `FORMULA_DEFS` (keyed by `target_pcs` / `new_sam` / `avg_sec` / `avg_min` / `actual_eff` / `actual_pcs` / `pass_rate`) and shows three blocks: **สูตร** (translated formula string), **คำอธิบาย** (translated description), and **ค่าที่คุณป้อน** (each def's `compute()` reads current form inputs and returns a substituted expression + result; returns `null` when inputs are missing → the modal shows `fx_no_data` instead). When adding a new computed field, add its `<label class="fx-label" data-fx="...">` in `index.html`, an entry in `FORMULA_DEFS`, and the `fx_formula_<key>` + `fx_desc_<key>` translation pair to all four language blocks (the translations test enforces parity).

**i18n** is a flat `translations` object (in `translations.js`) keyed by language code (`th`/`en`/`vn`/`la`) with string keys matching `data-key` attributes on elements (class `lang-text`). `changeLanguage()` walks the DOM and swaps text content (and `[data-key-placeholder]` attributes for input placeholders); `t(key)` is the lookup helper used inside JS-generated HTML (training cards, chart labels, compare table, N-row breakdown). When adding new UI copy, add the key to all four language blocks and reference it via `data-key="..."` (static markup) or `t('key')` (dynamically generated markup) — otherwise text falls back to Thai or the raw key. `test/translations.test.js` enforces this: it fails the build if `en`/`vn`/`la` are missing any key present in `th`, if any value is empty, or if a translation lost a `{placeholder}` token. Chosen language persists to `localStorage` under `csa_lang`.

**Auth + backend (Firebase).** `src/auth.js` initialises Firebase Auth + Firestore (with `persistentLocalCache` for offline resilience) when `import.meta.env.VITE_FIREBASE_API_KEY` is set — `FIREBASE_ENABLED` gates the whole layer, so a checkout without `.env` boots straight into the Phase-1 localStorage mode with no login gate. Sign-in is **employee-code only**: the user types a numeric code (e.g. `68020002`), `signInWithCode(code)` synthesises `<code>@ie-calc.internal` + password `<code>` and hits Firebase Auth's allowlist. The operator's UI shows just the code (`emailToCode(user.email)` strips the suffix); admin creates each account in Firebase Console. Per-user data lives at `users/{uid}/history/*` (evaluation snapshots) and `users/{uid}/tutorial/state` (single doc). Rules in [firestore.rules](firestore.rules) are the actual guard — the client `apiKey` is not a secret. See [docs/plan-backend-firebase.md](docs/plan-backend-firebase.md) for the design rationale.

**Boot (three phases, in `src/main.js`).** Phase A always runs — theme, language, SW register, no-zoom guards — so the splash / login card is themed and translated regardless of auth. Phase B `boot()` initialises Firebase, watches `onAuthChange`: no user → `showLoginOverlay()`, user → `enterApp(user)` once (subsequent snapshots ignored, guarded by `_appStarted`), mid-session sign-out → `window.location.reload()` so no per-user cache lingers. Phase C `enterApp(user)` awaits `subscribeHistory` + `subscribeTutorial` in parallel, runs `migrateLocalHistory` + `reconcileTutorial` (both idempotent per uid), then reveals the app. A **boot splash** (`#bootSplash` + `body.booting`) hides every other body child with `visibility: hidden !important` until `endBoot()` fires from either the login path or `enterApp()`, killing the flash-of-app-before-auth (~5 s on cold Firebase init). A 10 s timeout in `boot()` force-shows the login card if `onAuthChange` never fires (network died).

**Persistence — the seam pattern.** `src/history.js` and `src/tutorial.js` each own the "seam" between localStorage and Firestore: `loadHistory()` / `loadTutProgress()` return the Firestore-fed cache when `FIREBASE_ENABLED && isSignedIn()`, otherwise the local read; writes always hit localStorage first (offline fallback + fast synchronous re-read) and — when signed in — route through `fsSaveEntry` / `fsSaveTutorial`, which merge against the current cache so a stale save can't wipe cross-device progress. Consumers (`renderHistoryList`, `renderTutorial`, etc.) never touch storage directly.
- Form auto-save (`csa_form_v1`) in `app.js` — every `calculateAll()` call ends with `saveFormState()`; `restoreFormState()` runs once at init.
- History (`csa_history_v1`) in `history.js` — explicit "Save current" via `saveCurrentToHistory()` snapshots inputs + computed results + optional shift-handover note (`entry.note`, max 200 chars, editable per row). Capped at `HISTORY_MAX` (100), FIFO-trimmed. Compare view lets the user pick 2+ entries → side-by-side table. When signed in, the same shape is mirrored to `users/{uid}/history/{entryId}`; `subscribeHistory` keeps the cache fresh via `onSnapshot`.
- Tutorial progress (`csa_tutorial_v1`) in `tutorial.js` — `{ done, quiz, cert }`. When signed in, mirrored to `users/{uid}/tutorial/state` so a lesson finished on one phone stays finished after signing in on another. `mergeTutorialProgress` (pure, in `auth.js`, unit-tested) does the union merge: `done` is a union, quiz keeps the better result (passed > not-passed, higher pct at ties), cert keeps the earliest ts (first issue is canonical, reprint mustn't reset id/name/date).
- Theme (`csa_theme`), language (`csa_lang`), session count (`csa_session_count`, used by the PWA install-prompt gate), onboarding-seen (`csa_onboarded_v1`), feedback offline queue (`csa_feedback_queue_v1`, cap 20 entries), and per-uid one-shot flags `csa_migrated_<uid>` / `csa_tut_reconciled_<uid>` — each follows the same read-on-init / write-on-change pattern.

**Design tokens** (`style.css` §1): all colors are CSS custom properties on `:root`. A parallel dark token set applies under `@media (prefers-color-scheme: dark)` by default, or via `:root[data-theme="dark"]`/`[data-theme="light"]` when the user explicitly toggles (`toggleTheme()`, persisted to `csa_theme`). The hand-built SVG chart in `renderSVGChart()` draws with `var(--...)` tokens, so it re-themes automatically. Three semantic families to keep straight when adding UI:
- `--accent-*` (indigo) — brand, target / plan surfaces, primary actions. `--accent-grad` is **reserved for the primary CTA + brand mark only** (using it everywhere is what makes the app read as AI-scaffolded).
- `--accent-teal-*` — "actual / measured" surfaces (differentiates shop-floor readouts from the plan). Applied via `.actual-section` scope.
- `--status-{ok,warn,bad}-*` — threshold-driven ambient tint on result values. Semantic, never used as brand.

**External integrations, both feature-flagged in `app.js` / `state.js`:**
- Feedback modal opens from the header actions menu (`data-action="feedback"` in `src/wiring.js`) — the old floating `#feedbackBtn` is gone. Submits to a Google Form via `fetch(... mode: 'no-cors')` — controlled by `GFORM_ENABLED` / `GFORM.url` / `GFORM.entry.*`. `no-cors` means the fetch always resolves opaquely (server errors are invisible); the mitigation is: if `!navigator.onLine`, submissions get queued in `csa_feedback_queue_v1` and drained on `online` event (and once at startup). The real fix for reliable ACKs is a Cloudflare Worker / Supabase Edge proxy — not yet built.
- Google Analytics 4 is lazy-injected via `initGA4()` — controlled by `GA4_ENABLED` / `GA4_MEASUREMENT_ID`. Events are fired through `gaTrack(eventName, params)`; feature-usage events (`use_quality_section`, `use_training_plan`) are tracked once per session via the `_tracked` flags to avoid re-firing on every keystroke.

**PWA install + onboarding:**
- `beforeinstallprompt` is stashed on `window`; the header install chip (`#installBtn`) reveals only after the 2nd session (`csa_session_count`) and only when not already in standalone mode. Silent on iOS Safari (event never fires).
- First-run 3-screen onboarding tour (`#onboardingOverlay`) shows once, persisted via `csa_onboarded_v1`. Skip button always available. `showOnboardingIfNeeded()` runs from init.

**PWA/offline**: `src/sw.js` is the SW source; **vite-plugin-pwa (`injectManifest`)** rewrites `self.__WB_MANIFEST` at build time with the hashed asset filenames Vite emitted and copies the result to `dist/sw.js`. Uses **network-first with 3 s timeout**; fallback cascade: cached response → cached `/index.html` (for navigation requests) → synthetic 503. Never resolves to `undefined` (which would throw inside `respondWith` and show the browser's native offline page). Precache uses per-URL `cache.add(...).catch()` (not atomic `addAll`) so one 404 doesn't kill the whole install. `index.html` also sets no-cache HTTP meta tags so the HTML shell is never cached client-side — only the service worker's own cache controls offline behavior. `vercel.json` reinforces this with `Cache-Control: no-cache` for `/sw.js` + `/index.html` and `immutable, max-age=1y` for hashed `/assets/*`.

**Perf posture (locked, see Product priorities).** Bundle after Phase 3 rebuild: **~766 KB / gzip ~234 KB**. Obfuscator config in `vite.config.js` is deliberately light — `identifierNamesGenerator: hexadecimal`, `stringArray` with **no encoding**, minify + `disableConsoleOutput` — because the heavier passes (`controlFlowFlattening`, `deadCodeInjection`, `transformObjectKeys`, base64 `stringArrayEncoding`, `debugProtection`, `selfDefending`) each cost real runtime on cheap phones. Tutorial screenshots are preloaded in `openTutorial()` via `new Image().src = ...` for every distinct step image so navigating between steps is instant; the lesson `<img>` uses `loading="eager" decoding="async" fetchpriority="high"`. Firebase's SDK is `optimizeDeps.include`d so `npm run dev` doesn't round-trip hundreds of nested modules through the dev server on cold start.

**Export:**
- **CSV** (`exportCSV()` in `app.js`) — bilingual key/value rows via `csvBuild` / `csvRow` / `csvEscape` in `timeutil.js`. UTF-8 BOM prepended so Excel opens Thai correctly.
- **PDF** — browser's native "Save as PDF" via `printReport()` → `window.print()`. Print stylesheet (`@page A4 portrait`, forced color, single-column, safe-area-friendly, self-referential URLs) is authored to make the PDF audit-ready without shipping jsPDF or fighting Thai font embedding.
